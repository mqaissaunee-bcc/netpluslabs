Overview — what this lab is really teaching

An IPv4 address is a 32-bit number in dotted-decimal (e.g. 192.168.1.50). A subnet mask (e.g. 255.255.255.0, or /24) splits it into a network part and a host part. A device needs an address, a mask, a default gateway (the way off its own subnet), and a DNS server to actually use the network.

You'll configure addressing two ways — automatically with DHCP and by hand as static — on both Windows and Linux, then confirm each with verification commands. Doing it on both OSes is the point: the exam expects you to work in either.

DHCP vs static, in one lineDHCP = the pfSense server hands out a lease automatically; static = you type every value yourself. Static is for servers and infrastructure; DHCP is for everything else.

Walkthrough

Windows — DHCP then static

1Enable DHCP (Windows)

In Network Connections → Adapter → Properties → IPv4, choose Obtain an IP address automatically. Then confirm the lease from a command prompt:

ipconfig /all

Look for DHCP Enabled: Yes and a DHCP Server address. 📷 screenshot for your report

2Renew the lease if needed

ipconfig /release
ipconfig /renew

3Switch to static (Windows)

Back in the IPv4 properties, choose Use the following IP address and enter the address, mask, gateway, and DNS from your lab's addressing table. Verify:

ipconfig /all

Then prove it still reaches the gateway. 📷 screenshot for your report

ping 192.168.1.254

Linux (Mint) — DHCP then static

1View current addressing

ip address show

2DHCP on Linux

The lab uses the Network settings GUI (or dhclient from a terminal) to request a lease, then verifies with ip address show and a ping to the gateway.

3Static on Linux

Set the address/mask/gateway/DNS in Network settings, apply, and verify the same way. Confirm connectivity: 📷 screenshot for your report

ping -c 4 172.16.1.254

Class / rangeCIDRTypical use
10.0.0.0 – 10.255.255.255/8Private (RFC 1918), large networks

192.168.0.0 – 192.168.255.255/16Private (RFC 1918), home/small office
169.254.0.0 – 169.254.255.255/16APIPA — self-assigned when DHCP fails
127.0.0.0/8Loopback (127.0.0.1 = localhost)
Subnet mask
Marks which bits are network vs host. 255.255.255.0 = /24.
Default gateway
The router address a host sends traffic to when the destination is on another subnet.
APIPA (169.254.x.x)
A link-local address a host assigns itself when it can't reach a DHCP server — a sign DHCP failed.
Lease
The time-limited assignment DHCP gives a client; ipconfig /renew requests a new one.

Exam relevance (N10-009)

  • Recognize the RFC 1918 private ranges and APIPA on sight — extremely common exam items.
  • Know the four values a host needs: IP, mask, gateway, DNS.
  • A 169.254.x.x address is the exam's signal for 'DHCP isn't working.'
  • Know both toolsets: Windows ipconfig family and Linux ip address / ifconfig.

Check yourself

1. A host shows 169.254.10.5. What does that tell you?

It's an APIPA address — the host failed to get a DHCP lease and self-assigned. Troubleshoot the link and the DHCP server.

2. What does /24 mean as a mask?

The first 24 bits are network (255.255.255.0), leaving 8 bits (254 usable hosts) for the host portion.

3. Which command shows the DHCP server and lease on Windows?

ipconfig /all — it lists the DHCP server, lease times, gateway, and DNS.

4. Why give a server a static address instead of DHCP?

So its address never changes — clients and DNS records depend on it staying put.
