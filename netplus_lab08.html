Overview — what this lab is really teaching

A switch forwards frames at Layer 2 using a MAC address table. A managed switch adds the features that make real networks work: identity and access control, VLANs to segment one physical switch into many logical networks, trunks to carry multiple VLANs between switches, port security to lock a port to known MACs, and link aggregation to bond ports for more bandwidth and redundancy.

You configure all of these on two switches (SW1, SW2), verify each with show commands, and test remote access over Telnet and SSH.

VLAN + trunk, the core ideaA VLAN is a broadcast domain you define in software — ports in VLAN 10 can't talk directly to VLAN 20 without a router. A trunk is a single link that carries many VLANs between switches, tagging each frame so the other side knows which VLAN it belongs to.

Task 2 - Ethernet Switching

1 Frame Forwarding - Sending unicast frames from a specific source port to a specific destination port. This is the most common type of switch communication when one device wants to send data to another device. This is 1-to-1 communication, hence the term unicast.

2 Frame Flooding - Sending unicast frames to all ports in the switch having connected devices. Switches flood when they receive frames with destination MAC addresses that are not in its MAC table. When a destination device replies, the switch will learn its MAC address and add it to the table.

3 Frame Broadcasting/Multicasting - Sending broadcast frames to all ports, or multicast frames to a group of ports, to devices connected to the switch. This is used when information needs to be sent to all (broadcast), or a group (multicast) of devices. It is also important to remember that if switches connect to other switches, broadcast, multicast and unicast flood frames are also sent between them. The devices connected to switch ports also build a MAC table. In PCs, this table is known as the ARP cache. In other networking devices, such as routers, this table is known as the ARP table. ARP (Address Resolution Protocol) is a LAN protocol that maps unknown MAC addresses to known IPv4 addresses. This protocol is used by devices to learn the MAC addresses of other devices they need to communicate with in the same LAN. In this lab, we will be observing these tables. Switches can also be connected together to extend the LAN from one location to another, or merely to add more ports to accommodate more devices. Connections made between switches are called trunks. Trunks carry data between switches, and if VLANs are configured, between VLANs. It is important to know how switches work and how to configure them in a network. Familiarize yourself with the switching topology above. In this lab, all the PCs (PC1 through PC8) have been preconfigured with both IPv4 and IPv6 addresses. Notice PC1 IP addresses (1). We will not be using them all at once. The Admin server (2) will be used for management purposes. Notice the Trunk ports (9-12) between SW1 and SW2, and the blue oval labeled LAG (3). The combination of trunk ports forms a Link Aggregation Group (LAG). You will be configuring LAG later in the lab. Also notice the Switch Addressing table with VLAN addresses (4). You will be using those when configuring VLANs.

Task 4 - Switch Port Security

Task 4.1 - Configure and Verify Port Security

1 Starting with SW1, type show ports to view all the ports on SW1 and their characteristics. Notice that SW1 has 12 ports (1). The Port State, Link State, Speed, and Duplex (2) are listed for each port. The legend (3) describes the characters used in the Port States and Link States in (2). Notice in (2) that the Port State for all ports is E (Enabled), and ports 1-5 and 9-12 are A (active). Ports 6-8 are R (Ready), but not Active. The Speed for the Active ports is 100, which means that they are 100Mbs links. FULL means that those ports can operate in full- duplex mode, meaning that they can send and receive data simultaneously.

2 From the show ports command above, we can assume that ports 6-8 do not have any devices connected to them since the speed and duplex fields are blank (4). These ports should be disabled. Press the esc key to exit.

3 To disable ports 6-8 in SW1, type disable ports 6-8, and then press Enter. View the ports in SW1 again by typing show ports, and then press Enter. Notice that ports 6-8 are now showing the letter D under Port State, meaning that these ports are disabled.

4 Next, you will configure MAC locking on the ports that have end user devices connected to them. These are ports 1-5. To enable MAC locking in SW1 for these ports, type enable mac-locking ports 1-5, and then press Enter. Next, type configure mac-locking ports 1-5 first-arrival limit-learning 1, and then press Enter. This command will allow ports 1-5 to learn the MAC address from the first frame that enters these ports from a device plugged into these ports. The limit-learning 1 command will allow ports 1-5 to only learn one MAC address.

5 To verify that port security has been properly configured, type show mac-locking ports 1-5. Notice on the legend that ena means MAC locking is Enabled (1). Also notice that ports 1-5 are enabled, as indicated by the ena next to each port under MAC Lock Stat (2). Under Last Violating MAC Address, notice that all MAC addresses are 00:00:00:00:00:00 (3), meaning that no MAC addresses have caused a violation.

Exam relevance (N10-009)

  • VLANs, 802.1Q trunking, native VLAN — heavily tested under objective 2.2.
  • Port security / MAC filtering as an access-control measure.
  • Link aggregation (LACP / 802.3ad) for bandwidth and redundancy.
  • SSH over Telnet for secure management; know the security difference.
  • Know STP prevents switching loops (concept-level) once redundant links exist.

Check yourself

1. Two PCs in VLAN 10 on different switches can't ping. The access ports are correct. What's wrong?

The link between the switches isn't a trunk (or doesn't carry VLAN 10). A trunk with 802.1Q tagging is needed to extend the VLAN between switches.

2. Why bond four ports with LACP instead of using one?

More aggregate bandwidth and redundancy — traffic is shared across the links, and the bundle survives a single link failure.

3. Why prefer SSH over Telnet for switch management?

Telnet sends everything — including credentials — in cleartext; SSH encrypts the session.

4. What stops frames from an unknown device on a MAC-locked port?

Port security (MAC-locking) — only the learned/allowed MACs are permitted; others are blocked.
