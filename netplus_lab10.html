Overview — what this lab is really teaching

You can't manage what you can't see or correlate. This lab sets up the three services that make a network observable and maintainable:

  • NTP (UDP 123) — synchronizes clocks across devices so logs and events line up. Without synced time, correlating an incident across devices is nearly impossible.
  • SNMP (UDP 161, traps 162) — lets a monitoring station (NMS) query device health and receive alerts. You configure pfSense as an SNMP agent and poll it from Windows.
  • Syslog (UDP 514) — ships log messages to a central server so records survive even if a device fails, and all logs live in one searchable place.
Why these three go togetherNTP makes timestamps trustworthy, SNMP tells you how devices are doing, and syslog keeps the record of what happened. Together they're the backbone of network operations.

Walkthrough

Network Time Protocol (NTP)

1Configure pfSense as the NTP server

Enable the NTP service on pfSense so clients can sync to it. 📷 screenshot for your report

2Point a Windows client at it and verify

Configure WinOS to use the pfSense NTP server, then confirm synchronization from a command prompt with the w32tm tool: 📷 screenshot for your report

w32tm /query /peers
w32tm /resync

Simple Network Management Protocol (SNMP)

1Enable the SNMP agent on pfSense

Turn on the SNMP daemon on pfSense and set a community string (the SNMP v1/v2c 'password'). This makes pfSense queryable. 📷 screenshot for your report

2Poll it from an SNMP manager in Windows

Use the SNMP manager (NMS) on WinOS to run an SNMP GET against pfSense and read values (uptime, interface stats, etc.). Confirm pfSense appears as a managed agent. 📷 screenshot for your report

Syslog

1Configure a device as a syslog forwarder

Point a device's logging at the central syslog server's IP (UDP 514). 📷 screenshot for your report

2Set up and use the syslog server

Run a syslog server on WinOS, generate some log events, and confirm the messages arrive centrally — timestamped consistently thanks to NTP. 📷 screenshot for your report

Monitoring reference

ServicePortRole
NTPUDP 123Clock synchronization
SNMP (poll/GET)UDP 161Manager queries agent for data
SNMP trapUDP 162Agent pushes an alert to the manager
SyslogUDP 514Devices forward log messages to a central server
NMS
Network Management Station — the monitoring server that polls SNMP agents and collects traps.
SNMP community string
A shared secret in SNMP v1/v2c; SNMPv3 adds real auth and encryption and is preferred.
MIB / OID
The structured catalog (MIB) of values an agent exposes, each identified by an OID.
Syslog severity
Levels 0 (Emergency) to 7 (Debug) that rank log message importance.
Why centralize logs
So records survive a device failure and can be searched/correlated in one place (a SIEM extends this).

Where people get stuck

SymptomLikely causeFix
Client won't sync timeNTP blocked (UDP 123) or server not reachableConfirm the NTP service is up on pfSense and UDP 123 is permitted; w32tm /resync.
SNMP GET returns nothingWrong community string or SNMP not enabledMatch the community string exactly and confirm the SNMP daemon is running on the agent.
No logs on the syslog serverForwarder pointed at wrong IP, or UDP 514 blockedSet the correct server IP on the device and allow UDP 514; confirm the server is listening.
Timestamps don't line upDevices not NTP-syncedFix NTP first — log correlation depends on synchronized clocks.

Exam relevance (N10-009)

  • Memorize the ports: NTP 123, SNMP 161, SNMP trap 162, Syslog 514 (all UDP).
  • Know SNMP poll (GET) vs trap, and that SNMPv3 adds authentication/encryption.
  • Understand syslog severity levels and why centralized logging matters.
  • Know NTP's role in making logs/events correlatable — objective 3.2 monitoring.

Check yourself

1. An SNMP agent pushes an unsolicited alert to the NMS. Poll or trap, and what port?

A trap, on UDP 162. (Polling/GET uses UDP 161.)

2. Why is NTP a prerequisite for useful logging?

Without synchronized clocks, timestamps across devices don't line up, making incident correlation unreliable.

3. What's the security problem with SNMP v2c, and the fix?

Its community string is sent in cleartext with no encryption. SNMPv3 adds authentication and encryption.

4. Where do syslog messages go in this lab, and on what port?

To a central syslog server on UDP 514, so logs are retained and searchable in one place.
