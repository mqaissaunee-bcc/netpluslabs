Overview — what this lab is really teaching

Troubleshooting is mostly knowing which command answers which question. This lab drills the core toolkit on Windows (with Linux equivalents) so the right tool is reflex:

  • ipconfig / ifconfig / ip — what is my addressing?
  • ping — can I reach that host at all?
  • tracert / traceroute — where along the path does it break?
  • arp — what MAC maps to that IP on my local segment?
  • netstat — what connections and ports are open on this host?
Work the layers bottom-upCheck your own address (ipconfig), then the gateway (ping), then a remote host (ping), then the path (tracert), then name resolution. Isolating where it fails is half the battle.

Task 2.5 - Using the trace route Command

1 From the WinOS command prompt, type tracert 192.168.1.254, and then press Enter to do a trace route to the pfSense LAN interface.

2 Notice that WinOS is Tracing a route to 192.168.1.254 over a maximum of 30 hops (1). A hop is a networking device such as a router or firewall that a packet passes through. The default is a maximum of 30 hops. In the trace route output, it took 1 hop to get to the final destination of 192.168.1.254, and it took <1ms (2) for each trace route packet to reach that hop and receive a reply. Notice the final line states Trace complete (3), indicating a successful trace route.

3 Let's attempt to trace route to the WAN interface of pfSense. Type tracert 172.16.1.254, and then press Enter.

4 WinOS is Tracing a route to 172.16.1.254 over a maximum of 30 hops (1). Notice that it took 1 hop (2) to reach the final destination. This path displayed the time in milli seconds (ms) for a packet to reach each hop and reply (2). Notice the final line states Trace complete (3) ,indicating a successful trace route. Like extended ping, there is also an extended trace route. Extended trace route allows an administrator to specify parameters to do more in-depth tracing. Some parameters that can be specified in an extended trace route are: maximum number of hops, time to wait for each reply, source address, and more. In the following steps, you will be using some of these parameters with extended trace route.

5 At the WinOS command prompt, type tracert, and then press Enter. You are presented with the extended tracert Usage (1) and all the Options (2).

6 From command prompt, type tracert -h 3 172.16.1.254, and then press Enter. This command will trace from WinOS to the WAN interface of PfSense with a maximum of 3 hops. Notice this tried to trace over a maximum of 3 hops (1). Since PfSense is only one hop away, only one hop was displayed (2). Notice the final line states Trace complete (3), indicating a successful trace route.

Task 2.6 - Using the arp Command

1 From the Win OS command prompt, type arp, and then press Enter to see all the options available.

2 The arp command Displays and modifies the IP-to-Physical address translation tables used by ARP (1). The arp options are listed (2), and the Example: shows how to add a static entry into the ARP table, as well as how to display it (3).

3 Before we look at the ARP table for WinOS, ping the IP address for GNS3. This will allow WinOS to discover the MAN address of GNS3. Type ping 192.168.1.100, and then press Enter. Notice that pings are successful.

4 To display the arp table or arp cache, type arp -a, and then press Enter. The arp table for

Note

WinOS is displayed for the interface IP address of 192.168.1.20.

📸 Screenshot for your report: arp -a output showing IP↔MAC mappings

5 Notice that the arp table for WinOS has dynamically learned 2 Physical (MAC) mapped to 2 Internet (IP) Addresses (1). There are also 4 static MAC to IP mappings (2). These static entries are broadcast and multicast IPv4 addresses.

6 WinOs has dynamically learned the MAC and IP addresses of GNS3 and pfSense machines. Look at the topology to validate.

7 To delete the arp table, type arp -d, and then press Enter. Immediately type arp -a, and then press Enter to view the arp table again. Notice that all dynamic entries are gone. Notice there is one static entry. ARP tables can be built statically or dynamically. If you know the MAC and IP addresses of the device, you can manually add the mapping to the table using the arp -s command as discussed in step 2. However, it is easier to learn these addresses dynamically. To do this, we just need to generate some traffic to the destination IP address of the device we wish to learn the MAC address for.

8 Generate some traffic to 192.168.1.254 to learn its MAC address. Type ping 192.168.1.254, then press Enter. Next, type arp -a, and then press Enter to view the arp table again. Notice that WinOS added the MAC address of 00-50-56-99-40-c1 mapped to 192.168.1.254 to its arp table. What did WinOS do? It sent an ARP request to all devices on the LAN using a broadcast. All the other devices (GNS3 and pfSense) received it, but only pfSense replied with its MAC address, because it saw its own IP address in the ARP request sent by WinOS. pfSense sent an ARP reply back to WinOS, and then WinOS added the MAC address for pfSense to its arp table.

9 How does WinOS learn the MAC address of GNS3? Repeat step 8 using the IP address of GNS3. Send some frames to GNS3. Type ping 192.168.1.100, and then press Enter. Next, type arp - a to view the arp table. Notice the MAC to IP address mapping for GNS3 is now in the arp table for WinOS. 192.168.1.100 is mapped to 00-50-56-99-18-b0.

ping
Sends ICMP echo requests; replies prove Layer-3 reachability and show round-trip time.
tracert / traceroute
Maps the hop-by-hop path using incrementing TTL; pinpoints where a path fails.
arp
Shows/edits the IP-to-MAC cache; the glue between Layer 3 and Layer 2 on a local segment.
netstat
Lists sockets, connections, and listening ports on the local host.
ipconfig flags
/all full detail, /release / /renew DHCP, /flushdns clear DNS cache.

Exam relevance (N10-009)

  • Match the tool to the symptom — the heart of objective 5.5. Expect scenario questions.
  • Know Windows vs Linux equivalents (ipconfig↔ip, tracert↔traceroute).
  • Understand ARP's role and that arp -a reveals the IP↔MAC map (and underpins ARP spoofing).
  • Know netstat reveals open ports/connections, useful for both troubleshooting and security.

Check yourself

1. You can ping by IP but not by name. Which subsystem is broken?

DNS — connectivity is fine (IP works); name resolution is failing. Check DNS settings and flush the resolver cache.

2. Which command shows every hop between you and a destination?

tracert (Windows) / traceroute (Linux) — it reveals the path and where latency or failure occurs.

3. What does arp -a tell you, and why does it matter for security?

It shows the IP-to-MAC mappings your host has learned. Because ARP is unauthenticated, attackers can poison it (ARP spoofing) to intercept traffic.

4. Ping fails but the host is clearly up and serving web pages. Explain.

The host or a firewall is blocking ICMP. Ping isn't a definitive up/down test; try the actual service port.
