Overview — what this lab is really teaching

The OSI model is seven layers of abstraction that describe how data is packaged to cross a network. As data moves down the stack on the sender, each layer wraps it in its own header — that's encapsulation. On the receiver it moves up, and each layer strips its header off — de-encapsulation.

This lab makes that abstract idea concrete: you use Wireshark to capture live traffic and read the actual bytes each layer adds. You'll see an Ethernet frame (Layer 2), the IP packet inside it (Layer 3), the TCP/UDP segment inside that (Layer 4), and ICMP — the protocol ping rides on.

The one mental model to keepEach layer only talks to its peer on the other end. Layer 3 on your PC is having a conversation with Layer 3 on the server; it neither knows nor cares what Layer 2 did to carry the message. Encapsulation is how that illusion is maintained.

Capture walkthrough

Task 2 — Capture and examine Ethernet frames

1Start a capture

Open Wireshark, pick the active interface, and start capturing. Generate a little traffic so there's something to read.

ping 192.168.1.254

2Read the frame header (Layer 2)

Click any packet and expand Ethernet II. Note the destination and source MAC addresses (48-bit, shown as aa:bb:cc:...) and the EtherType (0x0800 = IPv4). That's the Layer-2 envelope. 📷 screenshot for your report

Task 3 — TCP and UDP headers (Layer 4)

1Examine a TCP segment

Filter for a TCP conversation and expand Transmission Control Protocol. Identify the source/destination ports, sequence and acknowledgment numbers, and the flags (SYN, ACK, FIN). This is how TCP delivers reliably and in order.

tcp

2Examine a UDP datagram

Now filter for UDP and expand it. Notice how much smaller the header is — just source port, destination port, length, checksum. No sequence numbers, no handshake. UDP trades reliability for speed. 📷 screenshot for your report

udp

Task 4 — IP header (Layer 3)

1Read the packet header

Expand Internet Protocol Version 4. Find the source and destination IP, the TTL (time to live — decremented by each router), and the Protocol field (1=ICMP, 6=TCP, 17=UDP). The IP header is what routers read to forward the packet.

Task 5 — ICMP packets

1Examine ping echo request/reply

Filter for ICMP. You'll see Echo (ping) request (type 8) and Echo reply (type 0) pairs. ICMP is the Layer-3 helper protocol that ping and traceroute depend on. 📷 screenshot for your report

icmp

Adding each layer's header as data moves down the stack on the sender.
De-encapsulation
Stripping each header as data moves up the stack on the receiver.
PDU
Protocol Data Unit — the name for the data+header at a given layer (frame, packet, segment).
Display filter
Wireshark expression (e.g. tcp.port==80) that shows only matching packets without discarding the capture.

Where people get stuck

SymptomLikely causeFix
Capture shows nothingWrong interface selected, or no traffic generatedPick the interface with the live IP; run a ping to create packets.
Too many packets to readEverything captured at onceApply a display filter — icmp, tcp, udp, or ip.addr==192.168.1.254.
Can't tell TCP from UDPLooking at the wrong layerExpand the Layer-4 block; TCP has seq/ack + flags, UDP has only 4 fields.
MAC vs IP confusionMixing Layer 2 and Layer 3MAC = Ethernet header (local delivery); IP = IP header (end-to-end). Both are in every routed packet.

Exam relevance (N10-009)

  • Know the seven layers in order and the PDU name at each — a classic exam item. Mnemonic: All People Seem To Need Data Processing (7→1).
  • Match protocols to layers: TCP/UDP = 4, IP/ICMP = 3, Ethernet/ARP = 2.
  • Know the protocol field values and common EtherTypes above.
  • Understand encapsulation order and that each layer communicates with its peer layer.
  • Wireshark is the tool the exam expects you to reach for to analyze traffic (objective 5.5).

Check yourself

1. At which layer is a PDU called a frame, and what addressing does it use?

Layer 2 (Data Link). It uses 48-bit MAC addresses for local, hop-to-hop delivery.

2. You see a packet with IP protocol field = 17. What's inside?

A UDP datagram. (1 = ICMP, 6 = TCP, 17 = UDP.)

3. Why does a UDP header have no sequence numbers?

UDP is connectionless and unreliable by design — it doesn't track order or guarantee delivery, which is why it's smaller and faster than TCP.

4. What happens to the TTL field as a packet crosses routers?

Each router decrements it by 1. At 0 the packet is dropped and an ICMP time exceeded is returned — this is exactly how traceroute works.
