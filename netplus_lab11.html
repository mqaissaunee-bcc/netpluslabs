Overview — what this lab is really teaching

A device configuration represents hours of work and the network's correct behavior. If a device dies or a change breaks something, a config backup is what gets you running again fast. This lab uses TFTP (UDP 69) — the simplest file-transfer protocol — to back up and restore a router config.

You configure one VyOS router as a TFTP server, back up the config from a TFTP client to it, then restore it — the full save-and-recover cycle.

TFTP has no securityTFTP has no authentication and no encryption — fine inside an isolated lab, but for real backups prefer SCP/SFTP (over SSH). Know this distinction for the exam.
config.bootOn VyOS the saved configuration file is config.boot. That's the file you back up and the one the router loads at boot.

Walkthrough

Configure a router as a TFTP server

1Enable the TFTP service

configure
set service tftp-server listen-address 168.50.80.2
set service tftp-server directory /config/tftpboot
set service tftp-server allow-upload
commit ; save

Confirm the service is listening: 📷 screenshot for your report

show service

Back up the config (client → server)

1Push the running config to the TFTP server

From the client router, upload its config.boot to the server's tftpboot directory:

tftp -p -l /config/config.boot -r backup 168.50.80.2

Verify the backup file now exists on the server. 📷 screenshot for your report

Restore the config (server → client)

1Pull the backup back down

tftp -g -r /config/tftpboot -r backup 168.50.80.2

Then load/boot the restored configuration and confirm the device is back to the saved state. 📷 screenshot for your report

Backup reference

ProtocolPortSecurityUse
TFTPUDP 69NoneQuick config transfers on trusted networks
FTPTCP 20/21CleartextFile transfer (insecure)
SFTPTCP 22 (SSH)EncryptedSecure file transfer — preferred
SCPTCP 22 (SSH)EncryptedSecure copy — preferred for backups
config.boot
VyOS's saved startup configuration file — the thing you back up.
Running vs startup config
Running = active in memory now; startup = what loads at boot. save writes running to startup.
Why back up
Fast recovery after hardware failure or a bad change; also for auditing and change tracking.
3-2-1 rule
Keep 3 copies, on 2 media types, with 1 off-site — standard backup hygiene.
tftp flags
-p put (upload), -g get (download), -l local file, -r remote file.

Exam relevance (N10-009)

  • Know TFTP = UDP 69, and that it has no auth/encryption — contrast with SFTP/SCP (TCP 22).
  • Understand running vs startup config and why backups matter for recovery.
  • Know configuration backup/restore as a standard operational procedure (objective 3.1).
  • Recognize the 3-2-1 backup rule as best practice.

Check yourself

1. Why wouldn't you use TFTP to back up production device configs over the Internet?

TFTP has no authentication or encryption — the config (including secrets) would cross in cleartext. Use SCP/SFTP instead.

2. What's the difference between running and startup config?

Running is active in memory right now; startup is what loads at boot. Saving writes running → startup (on VyOS, save writes config.boot).

3. Your TFTP upload is refused. Most likely config setting?

allow-upload isn't enabled — TFTP servers are read-only unless you permit uploads.

4. State the 3-2-1 backup rule.

3 copies of the data, on 2 different media types, with 1 copy stored off-site.
