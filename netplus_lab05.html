Overview — what this lab is really teaching

Virtualization runs multiple operating systems on one physical machine by abstracting the hardware with a hypervisor. The cloud is virtualization delivered as a service over the network. Understanding one makes the other make sense — which is why this lab has you build a VM by hand.

You enable Hyper-V (a hypervisor) in Windows, create a VM, install Xubuntu as the guest OS, explore VM operations, and take checkpoints/snapshots so you can roll back.

Type 1 vs Type 2 — know the difference coldType 1 (bare-metal) runs directly on hardware (ESXi, Hyper-V on Server, Proxmox) — for data centers. Type 2 (hosted) runs on top of an existing OS (VirtualBox, VMware Workstation) — for desktops. Hyper-V here behaves as the hosted case.

Walkthrough

Install the hypervisor & build a VM

1Enable Hyper-V

Add the Hyper-V feature (Server Manager → Add Roles and Features, or Turn Windows features on or off). Reboot if prompted. 📷 screenshot for your report

2Create a new virtual machine

Open Hyper-V Manager → New → Virtual Machine. Set name, generation, memory, network (connect to a virtual switch), and a new virtual hard disk.

Install and run the guest OS

1Attach the install media & install Xubuntu

Point the VM's DVD drive at the Xubuntu ISO, start the VM, and run the installer. This is a full OS install inside the VM. 📷 screenshot for your report

2Explore VM operations

Use the File and Action menus: Start, Shut Down, Save, Pause, and Settings. Note that Save freezes state to disk, unlike a full shutdown.

Checkpoints / snapshots

1Create a checkpoint

With the VM running, Action → Checkpoint. This captures the VM's exact state so you can return to it. 📷 screenshot for your report

2Revert to the checkpoint

Make a change inside the guest, then Apply the earlier checkpoint and watch the change disappear. Snapshots are your safety net before risky changes. 📷 screenshot for your report

Cloud & virtualization reference

TermMeans
IaaSInfrastructure as a Service — rent VMs, storage, networking (you manage the OS up)
PaaSPlatform as a Service — rent a runtime/platform (you manage just the app)
SaaSSoftware as a Service — use finished software over the web (vendor manages all)
Public cloudShared provider infrastructure (AWS, Azure, GCP)
Private cloudCloud model on infrastructure dedicated to one organization
Hybrid cloudMix of public + private with orchestration between them
Hypervisor
Software that creates and runs VMs by abstracting physical hardware.
Type 1 (bare-metal)
Runs directly on hardware — data-center class.
Type 2 (hosted)
Runs on top of a host OS — desktop class.
Snapshot / checkpoint
A saved point-in-time VM state you can revert to.
Elasticity
A cloud's ability to scale resources up/down on demand.
VPC
Virtual Private Cloud — an isolated, private network segment inside a public cloud.

SymptomLikely causeFix

Checkpoint confusionMixing 'Save' with 'Checkpoint'Save = pause state to disk; Checkpoint = a revertible snapshot you can return to later.

  • Understand elasticity/scalability and snapshots as operational concepts.

Check yourself

1. You rent bare VMs and install your own OS and apps. Which service model?

IaaS — you manage from the operating system up; the provider manages the physical infrastructure.

2. ESXi installed directly on a server is which hypervisor type?

Type 1 (bare-metal) — it runs on the hardware with no host OS underneath.

3. Why take a checkpoint before a risky change?

So you can revert to the exact prior state if the change breaks the VM.

4. What's a hybrid cloud?

A combination of public and private cloud with orchestration that lets workloads/data move between them.
