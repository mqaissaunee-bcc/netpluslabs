Overview — what this lab is really teaching

A router connects different networks and decides, per packet, where to send it next by consulting its routing table. A route can be directly connected (the router's own interfaces), static (you typed it), or dynamic (learned by a protocol — next lab).

Here you configure static routes so R1 and R2 can reach each other's LANs, add a default route (0.0.0.0/0 — the 'everything else' route), and configure jumbo frames by raising the interface MTU. Everything is on VyOS routers in GNS3.

Static vs default routeA static route points to one specific destination network. A default route is the catch-all for any destination not matched by a more specific route — the 'gateway of last resort.'

Walkthrough

Basic addressing & reading the table

1Address the interfaces

configure
set interfaces ethernet eth0 address 192.168.10.1/24
commit ; save

2View the routing table

From operational mode, inspect what the router already knows (its directly-connected routes appear automatically):

show ip route
show ipv6 route

Note the codes in the left column — they tell you how each route was learned. 📷 screenshot for your report

Static routes

1Add a route to a remote LAN

Tell R1 how to reach R2's LAN by pointing at R2's interface as the next hop:

set protocols static route 172.16.31.0/24 next-hop <R2-ip>
set protocols static route6 2000:0b32:c0e9:3::/64 next-hop <R2-ipv6>
commit ; save

Verify it appears as an S route and that pings now reach the far LAN. 📷 screenshot for your report

show ip route
ping 172.16.31.3

Default route

1Add the gateway of last resort

Instead of a route per destination, point all unknown traffic at R2:

set protocols static route 0.0.0.0/0 next-hop <R2-ip>
set protocols static route6 ::/0 next-hop <R2-ipv6>
commit ; save

Confirm the S* default appears in the table. 📷 screenshot for your report

Jumbo frames

1Raise the MTU

Jumbo frames carry up to ~9000 bytes of payload, cutting per-packet overhead on links that support them end-to-end:

set interfaces ethernet eth0 mtu 9000
commit ; save
show interface ethernet eth0

Task 4 - The Routing Table

Task 4.1 - Viewing and Understanding the Routing Table

1 Navigate back to the R1 console. At the vyos@R1:~$ prompt, type show ip route to view the R1 IPv4 routing table.

2 Look at the output. The Codes: section (1) displays the different route types that could be learned by R1. Notice the directly connected networks (2). The C>* to the left of the IP addresses indicate that these are directly connected networks/subnets. Notice that the 168.50.80.0/30 and 192.168.10.0/24 are the networks assigned to R1 interfaces, eth0 and eth1. Also notice the timestamps at the end of each directly connected network entry. This represents how long ago that network was added to the routing table. The routing table tells us what networks can be reached. The R1 routing table can be interpreted as: R1 knows how to reach the 168.50.80.0/30 and 192.168.10.0/24 networks. They are directly connected to eth0 and eth1 respectively.

3 Repeat steps 1 and 2 to view the R2 IPv4 routing table. View the directly connected routes.

4 Next, we will view the IPv6 routing table on both routers. In the R1 console, type show ipv6 route, and then press Enter. Notice the directly connected IPv6 subnets (1) are visible. The IPv6 link-local addresses (2) have also been dynamically assigned.

5 Repeat step 4 above for R2.

Task 4.2 - Configure and Verify Static Routes

1 In the R1 console, type configure to enter configuration mode.

2 Next, type set protocols static route 172.16.31.0/24 next-hop 168.50.80.2, and then press Enter.

3 The previous command installs a static route in the R1 routing table to the 172.16.31.0/24 network (LAN 2). LAN 2 is reachable through the R2 eth0 IP address of 168.50.80.2 (next- hop). A hop is the next upstream router. Next, type commit, and then save. Type exit to exit configuration mode.

4 To view the R1 IPv4 routing table, type show ip route, and then press Enter.

5 Notice that the static route to 172.16.31.0/24 is now visible in the R1 routing table as: S>* 172.16.31.0/24 [1/0] via 168.50.80.2, eth1, 00:07:13 The S>* represents a static route. 172.16.31.0/24 is the remote destination network (LAN 2). In the [1/0] field, the 1 represents the default administrative distance and the 0 is known as the metric. Both of these values are important. These values in the [A/M] field will change based on types of routes. The via 168.50.80.2 means that the destination network of 172.16.31.0/24 can be reached through the next-hop IP address of 168.50.80.2. eth1 is the exit interface on R1, and 00:07:13 is the elapsed time since that route was learned by R1.

6 Since our topology is dual-stack, we also need to configure and verify IPv6 static routes between R1 and R2. Starting with R1, type configure to enter configuration mode.

7 Next, type the following command:

set protocols static route6 2000:0b32:c0e9:3::/64 next-hop
2000:0b32:c0e9:2::2

8 The last part of the command syntax wraps back to the beginning of the line. Just press Enter when complete.

9 Next, type commit, and then save. Type exit to exit configuration mode.

10 Verify configuration. Type show ipv6 route to view the R1 IPv6 routing table. Notice the IPv6 static route to 2000:0b32:c0e9:3::/64 now exists in the R1 routing table along with the previous routes viewed earlier.

Routing reference

Route codeMeans
CDirectly connected (the router's own interface subnet)
SStatic (manually configured)
S*Static default route (gateway of last resort)
O / R / BOSPF / RIP / BGP (dynamic — next lab)
Next hop
The IP of the neighboring router a packet is handed to on the way to its destination.
Default route
0.0.0.0/0 (IPv4) or ::/0 (IPv6) — matches any destination not covered by a more specific route.
Administrative distance
A route's trustworthiness ranking when multiple sources offer the same prefix (connected < static < dynamic).
Longest-prefix match
Routers pick the most specific matching route (the longest mask) first.
MTU / jumbo frame
Maximum frame payload; standard is 1500 bytes, jumbo is up to ~9000 — must match end-to-end.

Where people get stuck

SymptomLikely causeFix
Static route added but far LAN unreachableReturn route missing on the other routerRouting must work both ways — add the mirror-image route on R2 back to R1's LAN.
Route typed but not in tableWrong next-hop, or no commitConfirm the next-hop is reachable (directly connected) and that you committed.
Jumbo frames don't help / break pingsMTU mismatch along the pathEvery device on the path must support the same MTU; a single 1500-byte link fragments or drops jumbo frames.
Default route ignoredA more specific route matches firstThat's correct behavior — longest-prefix match wins; the default only catches unmatched traffic.

Exam relevance (N10-009)

  • Read a routing table and identify route source codes (C/S/O/etc.).
  • Know static vs default vs dynamic routing and when each fits.
  • Understand administrative distance and longest-prefix match as tie-breakers.
  • Know MTU / jumbo frames (9000) and that MTU must be consistent end-to-end.

Check yourself

1. You add a static route on R1 to R2's LAN but pings still fail. First thing to check?

The return path — R2 needs a route back to R1's LAN. Routing has to be bidirectional.

2. What does 0.0.0.0/0 represent?

The default route — the gateway of last resort for any destination not matched by a more specific route.

3. Two routes match a destination: /24 and /16. Which wins?

The /24 — longest-prefix (most specific) match always wins.

4. Why must jumbo frames be configured end-to-end?

A device with a smaller MTU along the path will fragment or drop the oversized frames, so a single mismatched hop defeats the benefit.
