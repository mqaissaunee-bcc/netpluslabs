Overview — what this lab is really teaching

People need to reach the network from outside — securely. This lab covers the two main tools: a VPN (an encrypted tunnel that puts a remote user on the network) and SSH (an encrypted remote shell for managing a single device).

You configure an OpenVPN server on pfSense, create a local VPN user, connect a client through the tunnel, and use SSH for secure device access.

VPN vs SSH — different jobsA VPN connects you to a whole network as if you were local. SSH gives you an encrypted command line on one device. Both encrypt; they solve different problems.

Remote-access VPN
Connects an individual user's device to the network (what you build here).
Site-to-site VPN
Permanently links two networks (e.g., two offices) over the Internet.
Split vs full tunnel
Split tunnel sends only corporate traffic through the VPN; full tunnel sends everything.
SSH key auth
Public-key authentication is stronger than passwords for SSH.
Out-of-band management
Reaching a device over a separate path (e.g., console) when the network is down.

Where people get stuck

SymptomLikely causeFix
VPN client won't connectWrong profile, port blocked, or user not createdVerify the OpenVPN server is running, the user exists, and the VPN port is reachable.
Connected but can't reach internal hostsTunnel network/routes or firewall rules missingConfirm the VPN pushes the right routes and firewall rules allow tunnel → LAN traffic.
Auth failsCredentials or auth backend mismatchCheck the user is in the backend the server authenticates against (local in this lab).
SSH refusedSSH service off or wrong port/credentialsEnable SSH on the device, confirm TCP 22, and use valid credentials (prefer keys).

Exam relevance (N10-009)

  • Know the ports: SSH 22, Telnet 23, RDP 3389, OpenVPN 1194, IPsec 500/4500, HTTPS 443.
  • Distinguish remote-access vs site-to-site VPN, and split vs full tunnel.
  • Know SSH replaces Telnet for secure CLI; prefer key-based auth.
  • Understand out-of-band management as a recovery path (objective 3.5).

Check yourself

1. A remote employee needs to access file shares as if in the office. VPN type?

A remote-access VPN — it connects the individual's device onto the corporate network.

2. SSH vs Telnet — why does it matter which you use?

Telnet is cleartext (credentials and data exposed); SSH encrypts the whole session. Always use SSH.

3. What's the difference between split and full tunnel?

Split tunnel routes only corporate traffic through the VPN (rest goes direct); full tunnel sends all traffic through the VPN.

4. Two branch offices need a permanent encrypted link. What do you deploy?

A site-to-site VPN between the offices' firewalls/routers.
